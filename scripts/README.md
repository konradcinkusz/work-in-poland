# Scripts

Every script is self-sufficient, reads secrets only from the environment (never inline), and fails
fast naming what is missing. Run any of them from anywhere inside the repository.

| Script | What it does |
|---|---|
| `setup.sh` / `setup.ps1` | One-command onboarding in numbered steps. `--check` (`-Check` on Windows) only reports what is missing, by name, and changes nothing |
| `generate-dev-key.mjs` | Prints (or `--out FILE` writes) a fresh RSA-2048 **PKCS#8** PEM — the format authservice expects — using only Node, so it works on Windows with no `openssl` |
| `dev-stack.sh up\|down\|logs\|prepare\|e2e` | The whole stack in containers (Postgres + authservice + API + web), no Aspire. The local mirror of CI's e2e job |
| `scan-secrets.sh [--staged\|--dir]` | The local mirror of the CI secret scan (full history by default) |
| `hooks/pre-commit` | The commit-time secret scan. Installed by `setup.sh`. **Refuses to commit without a scanner** — deliberate |
| `check-kernel-size.sh` | P2's mechanical ceiling: fails when `WorkInPoland.ServiceDefaults` exceeds 800 lines of C# |
| `check-links.mjs` | Fails when a relative link in any markdown file does not resolve |
| `add-migration.sh <Name>` | Adds an EF Core migration for the API's PostgreSQL schema |
| `smoke-public.sh <web> <api> <auth>` | The public-URL assertions the health checks cannot make (run by the deploy workflow) |

## Variables, by tier

The full list, with what degrades without each, is [`../secrets.env.example`](../secrets.env.example). In short:

| Tier | Variables |
|---|---|
| **always** | none locally — a fresh clone runs with an empty `.env` |
| **secret** | `Parameters:jwt-private-key` in `dotnet user-secrets` (generated by `setup.sh`); optional `Parameters:sendgrid-*`, `google-*`, `github-*` |
| **ci** | the GitHub environment secrets in [`../flyio/SECRETS.md`](../flyio/SECRETS.md) |
| **tuning** | `AUTHSERVICE_IMAGE`, `AUTHSERVICE_SOURCE`, `WAIT_SECONDS` (dev-stack) |

**The signing key's journey**, once: `dotnet user-secrets` (set by `setup.sh`) → AppHost parameter
`jwt-private-key` → authservice environment variable `Jwt__PrivateKeyPem` → configuration key
`Jwt:PrivateKeyPem`. In production the same value is a Fly secret set by the deploy workflow.
**A local key is never a production key.**

## Troubleshooting, keyed on the literal error text

| You see | Cause | Fix |
|---|---|---|
| `IDX10500: Signature validation failed. No security keys were provided` (API or web middleware) | authservice has no `jwks_uri` the validator can reach, or the signing key never reached it so its JWKS is empty | `curl <authservice>/.well-known/jwks.json` — `{"keys":[]}` means no key: re-run `scripts/setup.sh` (local) or check `JWT_PRIVATE_KEY_PEM` (deploy) |
| `IDX20803: Unable to obtain configuration from: 'http://…/.well-known/openid-configuration'` | `Jwt__Authority` points somewhere the API cannot reach, or it is `http://` without `Jwt__RequireHttpsMetadata=false` | fix the address; `false` is for private networks only |
| `IDX10205: Issuer validation failed` / `IDX10214: Audience validation failed` | the token's `iss`/`aud` is not `WorkInPoland` — authservice was started without `Jwt__Issuer`/`Jwt__Audience`, or an MCP token was sent to `/api/v1` | set both on authservice; MCP tokens only work on `/mcp/account` |
| `Jwt:PrivateKeyPem is not a readable PEM private key. Expected a PKCS#8 block` (authservice) | PKCS#1 (`BEGIN RSA PRIVATE KEY`) instead of PKCS#8 (`BEGIN PRIVATE KEY`), or the newlines arrived as a literal `\n` | regenerate with `node scripts/generate-dev-key.mjs`; the generator emits PKCS#8 |
| `Jwt:Algorithm is RS256 but no private key is configured` (authservice) | the key never reached the container — `flyio/authservice.fly.toml` sets `Jwt__Algorithm=RS256` on purpose, so a missing key fails the start loudly instead of silently falling back to a symmetric key and an empty JWKS | local: re-run `scripts/setup.sh`; deploy: check the `JWT_PRIVATE_KEY_PEM` environment secret |
| `openssl : The term 'openssl' is not recognized` | `openssl` is not a Windows command | use `node scripts/generate-dev-key.mjs` |
| `Password must be between 8 and 100 characters` / `Terms acceptance is required` on register | the web app's consent versions differ from authservice's `ConsentVersions` | make `CONSENT_TERMS_VERSION`/`CONSENT_PRIVACY_VERSION` equal to authservice's |
| `429` with `{"error":"rate_limited"}` from sign-in | authservice's per-IP `auth` limiter (20/min) and every request comes from the web app's one IP | wait, or see the gap in `flyio/INFRASTRUCTURE-ANALYSIS.md` |
| `Failed to connect to … 5432` / `password authentication failed for user "api"` | the Postgres first-boot script only runs on an **empty** volume, so rotated or new role passwords were never applied | `ALTER ROLE api PASSWORD '…'` (flyio/SECRETS.md, Rotation) |
| `initdb: directory "/var/lib/postgresql/data" exists but is not empty` | `PGDATA` points at the mount root where `lost+found` lives | `PGDATA` must be a subdirectory (`flyio/postgres.fly.toml` does this) |
| `Cannot pull ghcr.io/konradcinkusz/authservice:v0.3.4` in `dev-stack.sh` | offline, or ghcr.io blob storage is blocked | `AUTHSERVICE_SOURCE=/path/to/authservice scripts/dev-stack.sh up` builds it locally (read-only) |
| `commit refused: no secret scanner available` | neither gitleaks nor a running Docker daemon | install one — the refusal is the design (P5) |
| `NotSupportedException: … SqlServer …` at API startup | `DATABASE_PROVIDER=SqlServer` | PostgreSQL only — [ADR 0011](../docs/adr/0011-stack-deviations.md) |
